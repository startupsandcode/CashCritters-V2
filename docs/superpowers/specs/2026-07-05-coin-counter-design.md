## 2. Game Overview

**Coin Counter** is a 10-round, timed "count the coins" game. Each round shows a pile of pennies, nickels, dimes, and quarters. The player picks the correct total value from three multiple-choice options before a 10-second timer runs out. Difficulty ramps across the 10 rounds — small, same-denomination piles early on, larger mixed-denomination piles later.

The pedagogical intent: build fluency recognizing coin values and mentally summing mixed currency, a foundational skill the other games (which deal in dollar amounts) assume.

---

## 3. Game Loop

### Round Structure

Each round:

1. **Pile reveal** — a pile of coins renders on screen (see Section 5 for pile generation rules)
2. **Answer choices** — three dollar amounts render as tappable buttons: the correct total and two distractors
3. **Decision window** — 10-second countdown bar drains
4. **Resolution:**
   - Tap the correct total → round marked correct, brief affirming flash (e.g. "Correct! 🎉")
   - Tap a distractor → round marked incorrect, brief corrective flash showing the right answer (e.g. "Not quite — it was 47¢")
   - Timer expires with no tap → round marked incorrect, same corrective flash
5. Auto-advance to the next round after the flash (short fixed delay, no user action needed)

### Difficulty Ramp

| Rounds | Coin count | Denominations mixed |
|--------|-----------|----------------------|
| 1–3 (easy) | 2–3 coins | 1–2 (e.g. all pennies, or pennies + nickels) |
| 4–7 (medium) | 4–5 coins | 2–3 |
| 8–10 (hard) | 6–7 coins | up to all 4 |

### End of Game

After round 10, the game ends. The player's score (correct answers, 0–10) is saved to the database. The results screen shows:
- Final score ("You got 7/10 correct!")
- Round-by-round breakdown (pile shown small, correct/incorrect indicator)
- Leaderboard position
- "Play Again" button

---

## 4. Scoring

- **Score** = number of correct rounds, an integer 0–10
- Stored in the existing `GameScore` table with `gameId: "coin-counter"`
- Every completed game writes one row — multiple plays produce multiple rows
- Personal best = highest score across all of a user's rows
- Leaderboard = top 10 personal bests globally, via the existing `getLeaderboard` action (unchanged logic, just a different `gameId`)

## 5. Content Structure

Unlike Savings Race's static scenario list, coin piles are procedurally generated combinations of 4 coin values — a hardcoded list would be either huge or repetitive. Instead, `src/content/games/coin-counter.ts` exports generation logic, not fixed data.

```typescript
export type CoinDenomination = 1 | 5 | 10 | 25   // cent values

export interface CoinPile {
  coins: CoinDenomination[]   // e.g. [25, 25, 10, 1]
  totalCents: number          // sum of coins
}

export type DifficultyTier = "easy" | "medium" | "hard"

// Returns the difficulty tier for a given round number (1-10)
export function tierForRound(round: number): DifficultyTier

// Generates a random pile matching the tier's coin-count and
// denomination-variety rules from the table in Section 3
export function generatePile(tier: DifficultyTier): CoinPile

// Generates two distractor totals (in cents) for a given correct total:
// each is the correct total +/- one coin's value (5, 10, or 25 cents),
// clamped to be non-negative and never equal to the correct total or
// to each other. Returns exactly 2 distinct distractors.
export function generateDistractors(totalCents: number): [number, number]
```

### Generation Rules

- **Coin pool per tier** — easy draws only from 1–2 denominations chosen randomly per round (e.g. pennies only, or pennies+nickels); medium draws from 2–3; hard draws from all 4.
- **Coin count** — randomly chosen within the tier's range (Section 3 table).
- **Distractors** — generated by nudging the correct total by ±1/5/10/25 cents (picking a value present in, or plausible for, the pile) so wrong answers are "close" rather than wildly off, matching how a kid might miscount by one coin.
- **Answer order** — the 3 choices (1 correct + 2 distractors) are shuffled before rendering so the correct answer isn't always in the same position.

### Maximum Possible Score

Always 10 (one point per round, regardless of difficulty tier) — difficulty affects challenge, not point value.

## 7. Page Architecture

### `/games/coin-counter` — Server Component shell

- Calls `getLeaderboard("coin-counter")` to pre-fetch leaderboard
- Passes `leaderboard` and `personalBest` as props to `CoinCounterClient`
- No lock/gating — any logged-in user can play any time

### `CoinCounterClient` — Client Component

Owns all game state:

```typescript
type GamePhase = "intro" | "playing" | "result"

interface RoundRecord {
  pile: CoinPile
  choices: number[]        // 3 shuffled totals in cents
  selectedCents: number | null   // null if timed out
  correct: boolean
}

interface GameState {
  phase: GamePhase
  round: number             // 1-10
  score: number             // correct count so far
  rounds: RoundRecord[]     // filled in as the game progresses
}
```

**Game phases:**
- `intro` — shows rules + leaderboard, "Start Game" button
- `playing` — the 10-round loop: generate pile for current round's tier, render, run timer, resolve tap/timeout, show flash, advance
- `result` — score, round-by-round breakdown, updated leaderboard position, "Play Again"

On transition from `playing` → `result`: calls `saveGameScore("coin-counter", score)`, then `router.refresh()` to reload the leaderboard. Wrapped in try/catch — if the save fails, the results screen still renders (score just won't reach the leaderboard), matching Savings Race's error-handling posture.

### Timer Implementation

Same mechanism as Savings Race: `useEffect` + `setInterval` at 100ms ticks, 10000ms total per round, gated to the `"playing"` phase only.

### Coin Rendering

Coins render as styled `<div>` circles, no image assets:
- Penny: small, copper/orange-brown background, "1¢" label
- Nickel: medium, gray/silver background, "5¢" label
- Dime: small-medium, silver background, "10¢" label
- Quarter: largest, silver background, "25¢" label
- Pile layout: coins wrap in a loosely-packed flex container (slight random rotation per coin via inline style for a "scattered pile" look)
